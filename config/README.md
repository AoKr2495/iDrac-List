# 可编辑业务配置

这两份 JSON 为源码配置，不是业务数据库或日志，可随源码版本管理。修改后重启后端并刷新浏览器生效，无需重新编译前端。Docker 使用只读挂载的整个 config/ 目录，修改宿主文件后重启容器即可。

## PKF 默认补全：pkf.json

```json
{
  "default_prefix": "PKF26GR"
}
```

明年改为 `"default_prefix": "PKF27GR"` 即可。不要填 `PKF27GR00`：`00` 是编号补齐五位产生的，不属于前缀。输入 468、0468、00468 均补成 `PKF27GR00468`。

前缀保持 PKF + 两位年份 + GR 的已确认格式。只改变默认补全年份，不修改数据库内已有单号，不改变五位补零、大小写宽容、唯一性和排序。

年份优先顺序：显式输入带年份的单号 → 当前标签最近明确输入的年份上下文 → 配置年份与已有 Active/History 最大年份两者较大值。因此即使已有 26 年记录，配置改 27 后，新标签输入数字仍会补 27；明确输入 26gr468 仍得到 PKF26GR00468，并更新本标签上下文。改配置后刷新浏览器，以清除标签中旧的明确年份上下文。

## Validation 提醒：validation_reminders.json

文件已预留所有 6 个 Model × 3 个 OS，共 18 个空数组。例如可以这样填写对应部分：

```json
{
  "default": ["通用检查提示，可以留空"],
  "by_model_os": {
    "R250": {
      "xDome": ["检查 BIOS 配置", "检查 xDome 安装结果"],
      "CTD": [],
      "SRA": []
    }
  }
}
```

保留文件中的其他 Model 即可；上面是格式示例，不是预设检查要求。正式文件默认所有提醒为空，未擅自填写实际检查内容。

- default：所有 Server 共用的提醒，Model/OS 未填时也适用。
- by_model_os：按准确 Model、OS 匹配；支持 R250/R260/R450/R640/R660XS/SE50 与 xDome/CTD/SRA。
- 最终显示顺序为通用提醒在前，匹配组合提醒在后；空字符串/纯空白不显示，无任何内容时不显示提醒区。
- 每一项是普通文字，不执行 HTML、脚本或 Markdown；支持换行并保留文字排版。
- 仅在 Confirm Validation 弹窗显示，不增加勾选框、不新增确认门槛、不新增 Checklist 业务数据。Model/OS 仍可为空，不阻止 Validation。
- JSON 不支持注释，字符串必须用双引号；文件缺失或格式错误会明确阻止启动，不静默忽略配置。未知 Model/OS、非字符串提醒也会报错。

根 config.yaml 的 business.config_dir 指向此目录，默认 ./config；该路径相对 config.yaml 解析。变更挂载路径时同步修改 Compose。配置读取不写业务数据或业务审计，原业务操作和永久审计保持不变。
